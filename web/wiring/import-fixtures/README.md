# Import test corpus — manifest

**Purpose.** Drive automated tests for the paper-import backend when it is
built. Every file here is **synthetic** (generated by `_generate.py`, seeded
RNG, no real user library, no scraped metadata, no copyrighted abstract).
Re-generate with:

```bash
python3 web/wiring/import-fixtures/_generate.py
```

95 fixtures, ~1.9 MB total.

Companion documents:

- `../import-format-matrix.md` — which formats ship in which phase, and why.
- `../missing-states.md` — states the demo never designed (several are hit by
  fixtures in this corpus; they are cross-referenced below as `MS-IMP-nn`).
- `../escalations.md` — things that would need a UI change; **not** changed.

---

## Expected-outcome vocabulary

The vocabulary is the demo's own, taken from `import-resolver.js` and the
three import surfaces (Home wizard step 2, Build seed sidebar, Runs Add-papers
panel). Tests should assert against these, not against invented names.

**Per-file row** (`ki-file`, the `Parsing…` spinner settles into one of):

| Token | UI it maps to |
| --- | --- |
| `file:ok(N)` | `✓ N references` |
| `file:error("…")` | error glyph + red message text; nothing from this file enters review |

The demo's only per-file error string today is
`Unsupported format: use .bib, .ris, .csv, a DOI list, or PDFs`
(fired whenever the extension is not one of `bib ris csv txt zip pdf`).
Every other error message below is a **proposal** — new copy, so it needs
product sign-off before it ships (see `../escalations.md`, E-IMP-04).

**Per-entry row** (`ki-row`, `data-st`):

| Token | `data-st` | UI it maps to |
| --- | --- | --- |
| `entry:matched` | `ok` | *Matched* group, checkbox auto-checked |
| `entry:ambiguous` | `multi` | *Needs a decision* group, `N matches` pill, unchecked until resolved |
| `entry:no-match` | `none` | *Couldn't match* group, error-tint reason line, **not addable** |
| `entry:duplicate` | `dupe` | *Already in the corpus* / *In your seed set*, dimmed + disabled |

**`MS-IMP-nn`** — this fixture lands in a state the demo never drew. Do not
invent UI for it; the test should assert the backend contract and the
missing-states register carries the design question.

## Suggested test matrix

| Axis | Assertion |
| --- | --- |
| Parse | file row settles to the expected `file:ok(N)` / `file:error(…)` |
| Resolve | entry states match the expected `matched / ambiguous / no-match / duplicate` split |
| Accounting | `matched + ambiguous + no-match + duplicate == N`. **No entry may vanish** — this is the design's explicit promise ("anything unmatched is reported, never added silently") |
| Idempotence | importing the same file twice yields `entry:duplicate` on the second pass |
| Safety | no file is written outside the import staging dir; no HTML from a fixture executes |
| Budget | a fixture's S2 round-trips stay within the batch ceiling (500 ids per `/paper/batch` POST) |
