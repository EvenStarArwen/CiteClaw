# OmniKnowledge Design System (v1)

Derived from `Paper Card.dc.html` (the **source of truth** — a full Build-page mock: top bar, Papers sidebar, Pipeline canvas, Config panel). `Pipeline Block Card.dc.html` is an **archived exploration**; its colors/spacings are superseded — never copy from it.

Product: **OmniKnowledge** — builds citation-search pipelines over academic papers. Top-bar tabs: **Build** (done) · **Runs** · **Explore** (to be designed, reusing everything below).

## Foundations

**Fonts** (Google Fonts, already linked in Paper Card's helmet):
- Display/titles: `'Newsreader', serif`, weight 500, often `letter-spacing:-0.01em`
- UI: `'Hanken Grotesk', -apple-system, sans-serif` (400/500/600)
- **Never in a header/title row** (panel/section/card titles and their inline counts — e.g. papers-panel "N papers" `.lp-count`, "9 steps" `.plh-count`, `.v6d-head-c`): those stay sans (`--font-sans`) with `font-variant-numeric:tabular-nums` for digit alignment. Mono in a title reads as OS/browser chrome.
- Code / identifier IDs / bare metric values: `ui-monospace, monospace` — reserved for **standalone id codes** (RUN-07, FWD-02, SED-01, T01) and **pure numeric values** (dock/hero stat numbers, slider values, counts) where digit alignment reads as data. **Never mono for word+number status or time phrases** — elapsed timers ("12:38 elapsed"), degradation/retry tickers ("S2 batch retry 1/6 · backoff 4s"), phase labels, or any sentence: those use the sans UI font (`font-variant-numeric:tabular-nums` for aligned digits).
- **STRICT: mono is FORBIDDEN everywhere else.** Menu rows, menu item names, buttons, chips/pill labels, tooltips, placeholders, empty states, body copy — all sans. The ONLY legal mono uses are the id codes and bare numerals above (a `T##` lead inside a chip is fine; the chip's words are sans). A `/command` in a menu or a skill/token pill is a *name*, not code — sans. When in doubt: sans.

**Type scale** (px):
- Serif titles: 22 drill-view title · 20 panel title (Papers, config step) · 18 canvas title + card titles (`.pb-title`, detail head) · 16.5 paper-row title · 17 empty-state title. Always weight 500, line-height 1.15–1.32.
- UI text: 14 inputs · 13/13.5 body & buttons · 12/12.5 meta, secondary · 11.5 small meta/mono
- Labels (uppercase, 600): 11/`.06em` section headers (`--muted2`) · 11/`.07em` weight-700 field labels (`--fg2`) · 10.5/`.07em` micro labels & card kinds · 9.5/`.14em` canvas watermark tags (`.pl-tag`)
- **Dock metrics**: 20px mono, weight 600, `letter-spacing:-.01em`, `font-variant-numeric:tabular-nums`, `--fg` — the one headline number per monitor-panel group (total calls, total tokens), each followed by an 11px `--muted` unit word. The only 20px UI/mono step; everything else in a dock group is ≤12.5.
- Half-pixel sizes (10.5, 11.5, 12.5, 13.5, 16.5) are intentional.

**Color tokens** — all styling reads CSS vars from `.pc-root` (light values below; dark theme + 4 alt schemes switch via `data-theme` / `data-color` attrs on the root — reuse that block wholesale):
- Surfaces: `--bg` #f1ebdd page · `--panel`/`--dock-bg` #faf9f5 panels · `--canvas` #f8f5ee pipeline canvas · `--card` #fff · `--card2` #fdfcf9 raised rows · `--card-sel` / `--row-sel` / `--row-hover` selection tints · `--icon-bg` #f0ece1 icon tiles · `--group-bg` section wells = `color-mix(in oklab, var(--bg) 72%, var(--panel))` — a warm bg-family tint, NEVER a gray ink-alpha wash; in dark it sits *below* the panel (recessed = darker) · `--well-hover` = `var(--card)` — the ONLY hover fill for rows inside wells (both themes)
- Lines: `--border` #e4e1d6 · `--divider` #ece9df (hairlines inside panels)
- Ink: `--fg` #141413 · `--fg2` #57554e · `--muted` #6c6a64 · `--muted2` #8e8b82
- Brand accent: `--accent` #cc785c terracotta (+ `--accent-hover`) — links, selection, saved-star. **Never for destruction.** (Fern-green alternates live in the `Fern *` schemes; **Warm paper + terracotta is the shipped identity** — green surfaces didn't sit naturally on the warm paper base.)
- **Fern library** scheme = Sage library's green-tinted surfaces + the full fern identity package (tone-on-tone: sage neutrals and fern accent share one hue family, split by chroma/lightness roles). Same normalized cool-neutral `--v-*` band, ink bars, success merge as Fern & ink.
- **Success**: Warm paper keeps its own success green; the fern schemes merge `--success` into the accent. `--warning`/`--error` untouched everywhere.
- Primary action: `--primary` (ink) + `--primary-fg` + `--primary-hover`
- Status: `--success` · `--warning` · `--error` + `--error-bg` (destructive hover, invalid fields, error states). `--err-bg` is an accent-tint surface (banners), not destructive.
- Focus: `--ring` rgba(31,30,29,.12)
- Block-kind colors (`--v-*` + `-dot` pair): **teal = Database** · **gold = Citation** (Forward/Backward Searcher) · **purple = Semantics** · **rose = Reranker**. **Block icons** (24-viewBox, 1.9 stroke, round caps — same family as filter icons; canonical map `plIconSvg()` in Paper Card / `stepIcon()` in Runs, keyed by type or code prefix): Seed Set = star (star-to-seed metaphor) · Forward = ↗ arrow · Backward = ↙ arrow · Database Searcher = cylinder · Semantic = center dot + side arcs · Reranker = ranked bars. Icons always render in the kind-dot color and REPLACE the kind dot where applied: `.pb-ico` in canvas card heads (13px), canvas add-menus (13px), Build config header title (16px, before the name), Runs steps list rows (13px, queued = `--dot-sep`, active keeps the pulse), Runs step-details header (`.rd-ico` 28px `--icon-bg` tile). Kept as dots: paper-row provenance chips, mon rejection rows, run-status dots (different semantics). **Color-governance layering** (all schemes): neutrals do structure → one accent does brand + interaction → categorical hues appear ONLY as small identifiers (7px dots, ticks, thin rails — never area fills) → status reserved. The base `--v-*` family is normalized to one warm, muted lightness/chroma band (olive-sage, clay, mauve, gold hero) so no kind-color outshines terracotta; `Fern & ink` carries a cool-neutral variant of the same band.
- **Monitor bars** run through `--bar-g1/g2` (throughput) and `--bar-l1..l4` (LLM funnel) tokens — **ink monochrome in every scheme** (`--fg` mixed into `--panel` at 72/52/34/18%), with kind color surviving only in each panel's 7px dot. Never hardcode bar fills.
- Filter-type colors `--f1…--f7` (+`d` dot pair): year, citation, keyword, author, venue, llm, similarity — pipeline-filter identity ONLY. **Venue names on paper rows are fixed Faint caps** (no per-class colors, no tweak): `--muted2` 11px caps + `--muted2` dot in Build/Runs; on Explore the venue caps take the **topic ink** (`tpInk` = topic color mixed 72% toward `--fg`) alongside the leading `T##` chip — noise papers and `Not run yet` fall back to `--muted2`.

**Radii**: 16 panels · 12 cards, menus, popovers · 9 buttons, inputs, selects, icon buttons ≥30px · 8 menu items, small icon tiles, small buttons · 999 pills/chips · 50% dot/circular add-buttons.

**Elevation**: panel `var(--dock-shadow)` · resting card `0 1px 3px rgba(var(--sh),.06)` · hover card `0 3px 10px rgba(var(--sh),.09)` · selected canvas node `0 0 0 3px var(--ring), 0 3px 12px rgba(var(--sh),.1)` · **menus/popovers `0 14px 34px rgba(var(--sh),.16)`** (micro-menu `0 10px 26px .16`).

**Layout**: root 1600×900, `--bg` page, three 16px-radius panels (`--dock-bg`/`--canvas`, 1px `--border`) in a 14px-gap main, padded 8px top / 14px sides+bottom (tight to the top bar). The **app top bar is 58px**; **every panel header row is 56px tall**, padding-x 16–20, bottom `--divider` hairline. The Monitor dock has **no header row** — group titles carry identity; 208px tall. Panel content padding 20px. Scrollareas: thin scrollbar `--scroll`, edge fade mask, rubber-band via `rubber()`.

**Numbers (project-wide)**: any count rendered in UI chrome is **compact** — `< 1000` exact · `< 10k` one decimal, trailing `.0` dropped (`1.5k`, `2k`) · `< 1M` rounded (`123k`) · else `M` (`2.4M`). Canonical helper `kfmt(n)` (Paper Card + Runs); `kText(s)` compacts every number inside a sentence-style string. Never let a grouped literal (`1,002`) reach a fixed-width slot; keep the exact value in a `title` tooltip when precision matters. Numeric columns that repeat down a list get **fixed sub-column widths** (count right-aligned · connector word · total left-aligned) so digits and connectors line up row to row — never right-align the whole string as one unit. Exceptions: years, page numbers, and IDs stay literal.

## Interaction rules
**Hover**: neutral, always — rows/ghost buttons use `--row-hover`; **icon-only ghost buttons on cards/popovers use `--ghost-hover`** (`color-mix(in oklab, var(--fg) 9%, var(--card))` — darkens in light mode, *lightens* in dark; never a fixed tint like the old `--star-bg`, which was invisible on dark cards). Cards: border `--border`→`--muted2` + hover shadow. Accent appears only on *selected* things.
**Selection** (emphasis is ranked: the canvas node is the page's primary object, list rows are secondary):
- **Pipeline node (strongest)** `.pb-card[data-sel="1"]` — `--fg` border + `0 0 0 4px var(--ring), 0 8px 22px rgba(var(--sh),.14)`, `translateY(-1px)`, `--card` bg, mono code darkens to `--fg`, and the kind tick grows 26×2 → 58×3 (.2s `cubic-bezier(.22,.61,.36,1)`). Dark theme swaps the ring to `rgba(255,255,255,.16)`.
- **List row / navigator row (secondary)** — `--row-sel` bg + **3px accent left rail** (inset, top/bottom-inset & rounded r2 like `.rv-toci`); hover is always a **soft-rounded `--row-hover` fill (r8–10)** — never a hard-corner full-width fill, never a border-only hover. ONE language across `.rv-toci` (lit-review Contents), `.cf-filter` (Build filter pipeline), `.rn-step` (Runs steps, hover only — launcher, no persistent select), `.rn-run` (All-runs — uses this EXACT rounded rail + the 2-line menu-row layout above; never the old hard `inset 3px 0 0` full-height bar), `.rn-*` menu-style rows, and the topic-drill paper rows (padded r10 rows). **EXCEPTION — full-bleed hairline lists** (`.pr` paper rows in Build/Runs/Explore, topic Index rows): these are edge-to-edge rows in a divider grid, so both hover and selection fill **full-bleed square** (`--row-hover` / `--row-sel` + rail) — do NOT inset or round them. **card layout** uses a 1px `--accent` border + `--card-sel` bg instead (no rail — a rail reads wrong on a detached card). Titles stay `--fg`; never tint the title.
- **Filter row** — follows the navigator-row rule above: `--row-sel` bg + **3px accent** left rail (NOT the `--f*` kind color — accent = selection is app-wide). The filter's kind stays legible via its `.cf-node` icon + `.cf-type` label, which keep the `--f*` color. (The kind-colored rail survives only in the Runs step-cascade flow viz, where the rail encodes flow, not selection.)
- **Filter value preview** (`.cf-val`, one truncating line): summarise, never echo the config. Year `2023 – 2026` / `From 2023` / `Any year` · Citation `30 cites / year` / `No threshold` · Keyword `Abstract · 2 keywords` · LLM `Abstract · 1 query` · Venue `3 venues` / `Any venue` · Similarity `≥ 0.05 · unscored pass` / `No threshold`. Pattern = *target · count of things*, no operators, no rule text — the editor and its popover carry the detail. Long source strings (query text, β tails) live in `data-query` / `data-cur` on the row so the editor can round-trip them.
- **Paper card contract (ONE source — `paper-row.js`)**: every `.pr` list row in Build (search sidebar), Runs (accepted/rejected), and Explore (papers tab) is rendered by `window.KLPaperRow.prCardInner(p, opts)` — never re-authored per page. Anatomy: selection rail (`opts.railClass`), serif `.pr-title` (16.5, 2-line clamp), then an **icon-meta block** — venue row (`opts.lead` chip + landmark icon + `.pr-venue` caps in `opts.venueColor`) over a meta row (person + `.pr-authors` (grow, ellipsis) · quote + cites · calendar + year, 11px `--muted2`-stroke icons, **year pinned right**). `opts.topRight` hosts an absolute control (unused by shipped pages — no abstract icon anywhere); `opts.foot` appends page rows (Runs step chip + stats). Venue tone is fixed here (`--muted2`; Explore passes topic ink). Pages keep their own `.pr` wrapper, selection/hover paint, and click wiring, and load the module with `<script src="./paper-row.js">` in the helmet (guarded: renderers wait for `kl-paper-row-ready` if it hasn't loaded).
- **Paper row click** is the SAME on every page (no abstract icon button anywhere) and follows the § Card ↔ canvas interaction contract: click selects (`--row-sel` + rail, synced to the canvas where one exists) AND opens the abstract drill; exiting (Back or clicking the open row) keeps the row selected with only a locate ring on its node; clicking the still-marked row again drops everything; blank-canvas click also drops everything.
- Rule of thumb: **ink border + ring = the structural object being edited; accent = the content item the user picked.** Never stack both on one element, and never give a secondary list row more visual weight than the canvas node.
**Destructive**: hover `--error-bg` bg + `--error` icon/text (trash, remove-query, delete-step). Invalid fields: `--error` border + `--error-bg` ring + `.fc-err` message row.
**Focus (inputs)**: border `--fg2` + `box-shadow:0 0 0 3px var(--ring)`.
**Press**: `translateY(.5px)` or `scale(.86)` on icon tools.

- **Flow-chart pipeline (6d) connector engine** (default `pipelineStyle`): connectors are NOT hand-placed CSS — `pl6Ink(flow)` in Paper Card draws every wire, fork/merge bus, elbow, and arrowhead as per-element `.v6d-ink` SVGs measured from the laid-out DOM (rect-based, transform-safe, re-run by a ResizeObserver on tier changes). No button ships with fewer than these states; interactive == it must visibly react:

## Run semantics (Runs page)

- **Steps execute serially: exactly one step may be `active` at a time.** Every step before it is `done`, every step after it is `queued` — never render two running steps (nor two live pulsing status dots), even across parallel branches. Execution is serial; **structure is not** — see § Pipeline spine.
- **Waves = the parallel blocks.** `rnWaves()` groups consecutive steps that consume the SAME input (`in`) into one wave — that is exactly Build's `Parallel` group. RUN-37 reads 1 · 2 · 2 · 2. Branching is derived from the data, never hand-declared per view.
- **Step drill-in** (`.rn-drill`, opened by clicking a step row): 56px header = back button + serif title + `CODE · KIND · STEP n OF m` submeta + right-aligned status (breathing `--success` dot + "Running" / static dot + "Completed" / `--dot-sep` dot + "Pending"). Then the metric hero, the threaded stage cascade, then popovers.
- **Hero metrics** — expansion steps (Forward/Backward/Semantic/Database Searcher) carry **four**: papers in (previous step's output) · papers found by this step's expansion · kept · rejected. Only the expanded set enters the filter pipeline — the input papers are already accepted and bypass it — so every percentage and unit-square bar scales on the expanded count. Database Searcher has no input papers (an LLM agent writes its queries), so its first metric is the found count. Diversified Reranker does no expansion: its 4th metric is topics/communities and it has **no filters**, just one ranking stage.
- **Stage cascade**: inline-styled `.cf-filter` rows (the Build config vocabulary) threaded by a 2px `--border` spine carrying mono pass counts ("↓ 512 pass"); each row shows a 16-square unit bar (kind colour = still in · **unified neutral tint** `color-mix(in srgb, var(--muted) 42%, var(--panel))` = removed here, the same for every filter kind (`--error` tint only for seed fetch failures) · hollow outline = removed earlier) with the reject count + % in a right-hand meta column. Rows hover neutral; click pins the config popover with the filter-kind rail. Running steps stop at the last pending filter — no greyed "Kept" row.
- **Config popovers** mirror the Build editors field-for-field (From/To · Citations per year of age (β) · Search in/Query · Screen on/Model/Reasoning effort/Query n), rendered as stacked field rows: caps 11/700 `--fg2` label over an **outlined value block** (`--card2` bg + inset `--divider` ring, r8, padding 7×10, 12.5 `--fg` UI font, line-height 1.5 — never mono, never a two-column grid, never a deep `--bg` fill); max-height 360 with a stable scrollbar gutter, and an "Edit filter in Build" link that switches to Build, selects the step's own `.pb-card[data-code]` and opens that filter's editor. Rows with no Build counterpart (Source, Kept, the reranker's ranking stage) omit the link.
- **Neighborhood mode** ("Show neighborhood"): a local view holds a handful of nodes, so it overrides the main layout defaults on enter and restores them on exit — overlap prevention `full`, dissuade hubs on, scaling 7 (vs 3), node size range 3–12 (vs 5–22). The Layout/Style popover controls repaint to the local values while it is active.: every monitor stat is clickable — "Rejections by filter" rows, the Database API calls hero + Graph/Recommendation rows, the LLM tokens hero + usage rows (neutral `--row-hover` hover + pinned state, `title` hint). Click pins a `cfg-pop` card above the row — header = 6px source-colored dot + caps 10.5 label "‹Stat› · by step" — listing the metric per pipeline step (mono step code · step name · 600-weight mono count · %). **Bars use the step's kind color** (`--v-teal/gold/rose-dot` by code prefix), the one place kind color fills a bar, because rows ARE steps; the active step is marked "· so far". Style = fixed **Ink bars** (per-row 4px proportion bars).

## Monitor group states (Runs dock)

Each of the three Monitor groups (Rejections by filter · Database API calls · LLM token usage — titles carry the unit) is a `.mon-grp[data-key]` with four sub-states, painted by `monApply()`:
- **dash** (before the first run ever): mono 12 `--muted2` "—" per group (unchanged).
- **wait** (`.mon-wait`, run started but this group has no statistics yet): the group's real anatomy, empty — labels/numbers in `--muted2`, zeros for counts, "—" for rates/percents, bars as bare tracks (`color-mix(in oklab, var(--fg) 8%, var(--panel))`, unit squares all-empty), dots dimmed to a 14% ink tint — no caption line (the 256px dock has no spare height; the zeros and empty tracks carry the meaning) Sort controls stay hidden.
- **off** (`.mon-offmsg`, the pipeline will never use this group): one specific 12px `--muted` sentence — "This run's pipeline has no filter steps." / "makes no database calls." / "has no LLM steps." — instead of empty elements, in run *and* idle.
- **live**: the normal filled group; arrival from wait is a .3s opacity fade.
Demo wiring: during a replay each group goes live the moment the run first produces that kind of statistic (`monPaint`) — Database on the first API call, Rejections on the first removal, LLM on the first token. Real wiring drives `_monSt`/`_monOff` from run config + first-stat arrival and calls `monApply()`.

## Runs mock-data contract (`run-mock.js`)

**All mock data for the Runs page lives in `run-mock.js`, and nothing in it is a backend contract** — the file's header says so at length, and any session wiring real telemetry must ask what the engine actually emits instead of mirroring this. The previous inline tables are archived in `archive/runs-mock-v1.md` (+ a full page backup beside it).

**Division of labour.** The module owns *numbers and timing*; the page owns *words and pixels*. Wording ("5.2k in  62 passed", "7 of 7 seeds fetched") is built in `rnDataFrame()`, never in the module.

**Shapes.**
- *Run source* — `{ id, label, elapsed, dur, accepted, rejected, steps[], filters[], tokenMix, calls, tokens }`. `RUN37` is the only one today; a second demo case is a second object, not a code branch. Step rows carry `cuts: [year, citation, keyword, LLM-title, LLM-abstract, duplicate]`.
- *Run library* — `RUN_LIBRARY` (completed history) + `NEXT_RUN_NO`. No permanent live row: the page creates one on demand (`rnNewLiveRun`, first id `RUN-38`, incrementing) so Run 37 and its version chain are never overwritten.
- *Replay* — `makeReplay(source, cfg) -> { duration, frameAt(ms) }`. **A frame is a pure function of time**: no accumulator state, so the panel can resume after the user navigates away, seek, or freeze on Stop simply by asking for a different `t`. Frame fields are documented above `frameAt()`.

**Pacing (demo choices).** 13:01 of engine time in 1 minute; the on-screen elapsed clock ticks in real seconds — the demo compresses the work, never the visible wall clock. Time is split across *waves* (the parallel blocks) in proportion to the papers each handled, so `FWD-07` dominates as it did in reality; inside a wave the steps play **back to back**, splitting that wave's time in proportion to their own size — the wave states the parallel structure, execution stays serial (§ Run semantics: exactly one step is ever `active`). Papers trickle into the corpus across a step's screening window — the real engine only knows a verdict once abstract screening returns.

**Wiring on the page.** `run-mock.js` is a classic script loaded by the helmet resource shim (`window.KLRunMock` + a `kl-run-mock-ready` event; `mockReady()` re-renders once it lands). Starting a run — from any Build configuration, or the `runState: Running` tweak — calls `rplStart()`, which ticks `rplTick → rplPaint` every 320ms and drives, in one place: the hero PRISMA counts, the step spine, the accepted/rejected lists (`_rplAcc`/`_rplRej` prefixes of the corpus, redrawn on a slower beat and never while the user is touching the list), the citation network (`nvSync` streams one node per accepted paper, seeded from the WHOLE corpus so node ids stay stable), and the monitor dock (`monPaint`). Finishing converts the live row into a completed run at the top of the list and offers **Show in Explore** in the success banner; Stop freezes the current frame as the run's partial result.

## Resilience & status system

**Two surfaces, split by lifetime.** *Persistent app state* (the connection set: offline / server unreachable / restored) is **chrome, not a toast**: it lands in the **status-strip slot** (`.bn-strip` → `.bn-sb`) directly under the app's top bar, above the panels — the same slot as the Runs page's version mode bar (`.rn-modebar`), and the same treatment: inset rounded card (12px radius, gutter margins, tone-tinted fill + hairline border, no shadow), 12.5/500, icon · message · optional pill action · ✕ pushed right. It is **in the layout**: the strip dispatches `kl-banner-inset {h}`, each shell sets `--bn-inset` on its root, and every page adds it to its content's top padding (`main` / `.hm-scroll`) — a status the user cannot dismiss must never cover a control. One strip banner at a time. *Transient event feedback* (release available, export ready, run stopped) keeps the floating pill stack below. Pass `sticky: true` to route a banner to the strip.

**System banners** (`System Banners.dc.html`, mounted by both shells at z-80 above pages *and* Settings): app-level transient status only — in-panel problems stay `.anc`/refusal banners. Floating pill stack, top-center, 10px under the top bar (`top:68px`), newest on top, cap 4, non-blocking (wrapper `pointer-events:none`, pills re-enable). Pill = r11 (a soft card, **not** a lozenge — 999px reads as a toast toy at this width), `--card` bg, 1px `--border`, menu shadow, 12.5/500 `--fg`, single line: 14px icon · message · optional `·` + underlined action button (`.bn-a`, hover `--accent-hover`) · 22px ghost ✕. **Four tones**: notice (plain card, `--muted` icon) · warning (`--warning` 10% tint bg + 32% tinted border; 14% dark) · error (`--error` 10%/32%; 16% dark — blocking/fatal only) · success (`--success` 10%/32%; auto-hide ~4s). Motion: drop-in `translateY(-10px) scale(.97)`→none .22s pop ease; exit reverses and collapses max-height/margin so the stack closes ranks. Mono bits: `.bn-cd` countdown numbers, `.bn-mono` run ids; `<b>` = 600. **API**: document-level CustomEvents — `kl-banner` `{key, tone, msg(html), icon, action, onAction, ttl, spin}` (same key updates in place) and `kl-banner-hide` `{key}`; any page can dispatch (bubbling) — e.g. Runs' stop-complete success. **Connection set** (key `conn`, always `sticky` → the strip): offline = warning + wifi-off “You’re offline — showing the last synced data.” (sticky) · server unreachable = error + cloud-off “retrying in ‹N›s” live countdown + “Retry now” (probe swaps to spinner “checking…” ~1s; backoff 5→8→11→12s) · restored = success “Connection restored — data resynced.” (ttl 4s). Demo: `connection` + `bannerDemo` (All tones) tweaks; shells forward `connection`.

**Degradation — three tiers, and retries are NOT tier one.** A run that retries an S2 batch or a model call and recovers is the engine working; surfacing each attempt turns the run hero into a nervous ticker and trains users to ignore it. So: (1) **retries inside the budget → silent** — the monitor dock's API-calls and token counters already carry them, nothing renders in the hero; (2) **budget exhausted / a provider unreachable while the run still progresses → the in-panel warning block** (`.rn-wx`, under the run-id row): warning-tinted card (r10, `--warning` 8% bg / 30% border), triangle icon, one 12/600 line naming what is down and for how long, one 11.5 `--muted` line saying what it costs the run and that it will resume — persistent while it holds, never a ticker; (3) **backend unreachable / run dead → not the panel at all**, the app-level red `kl-banner` error tone. The `apiRetries` tweak (default **off**) plays tier 2. The same escalation applies to any future backend telemetry: silent → in-panel warning → app banner.

**Primary-action working states** (Runs; `.tb-run`/`.tb-stop`/`.rs-run`/`.rs-new`): the click is acknowledged the instant it lands — `btnBusy()` swaps content to spinner + “Starting…”/“Stopping…”, freezes the measured min-width (no toolbar reflow), suppresses pointer-events, opacity .85; `btnIdle()` restores when the button's state hides it. **Neutral ink, never warning/error** — a user-initiated wind-down is not a fault. The run hero owns a dedicated **phase row** (`.rn-phase`, between the id/elapsed row and the metric strip; enters/leaves by max-height + opacity with a negative-margin gap compensation, .26s `(.22,.61,.36,1)`): **starting** = 12px spinner + “Starting — contacting engine…”, metric strip dims to .35 with pulses paused, `.tb-stop` hidden (nothing acked to stop yet; the toolbar keeps the busy Run button) — clears when step 1 activates (usually <1s); **stopping** = spinner + “Stopping — saving partial results…” + right-aligned mono “stopping for ‹N›s” counter + 11.5 `--muted` sub-line ticking checkpoint stages (“Finishing the current batch… / Writing the checkpoint… / Saving partial results…”, ~3s each) — lives 10–30s, the active step keeps its pulse, then resolves to Idle · has history, marks the run Stopped (`--warning` dot, real duration), and fires a success banner “‹RUN-ID› stopped — partial results saved.” **Never attribute starting/stopping to a pipeline step.** Demo: `runPhase` tweak pins either phase for review.

**In-run degradation ticker** (`.rn-wx`, same hero slot, under the phase row): a quiet weather report while the engine backs off a provider — slow-spinning refresh icon + one sans 11.5 `--muted` line (“S2 batch retry 3/6 · backoff 12s”, “Gemini retry 2 · backoff 4s”). Not an error surface: the run is progressing, so no tone tint, no banner. One line, latest event wins; expands/collapses like the phase row; hidden whenever a phase row is up, outside the run state, and via the `apiRetries` tweak (default on).

**API-key verification** (Settings): chips probe on overlay open (staggered `Verifying…` spinner) and again on Save — footer reads “Verifying keys…”, and an invalid key **blocks the close** with red “‹Provider› key failed verification.” Chip states (mono 10.5/600 pill): `Not set` (neutral) · `Set` (neutral — unverified, shown while a key is being edited) · `Verifying…` (spinner) · `Valid` (`--success` dot pill) · `Rate-limited` / `Unreachable` (`--warning` dot pill + explanatory `title` tooltip — the key may still work, runs degrade instead of failing) · **`Invalid key`** (the loud one: `--error` pill, input takes the error border + ring, `.st-kerr` row under it: “‹Provider› refused this key — runs that use it are blocked until it’s replaced.”). Demo: `keyProbe` tweak picks the probe outcome.

## Grouping: the canvas view IS the control (Explore)

Topics (semantic space, topic model) and **communities (citation space, Leiden)** are the SAME group object with two instantiations: same card vocabulary, same drill anatomy, same hover/click→canvas behaviour. Only provenance, the `T##`/`C##` code and the colour sampling differ.

- **ONE control, no lens switcher.** Because grouping is pinned 1:1 to space (network ↔ communities, topic map ↔ topics), a separate `Semantic | Citation` seg was pure redundant state — it produced a nested tab bar in the left panel, a duplicate seg in the canvas header, and views whose meaning changed with the other control. The **canvas view switcher carries the grouping with it**: `setView` calls `setLens` (`network → cit`, `topics → sem`), and nothing else ever sets the lens.
  - Citation network → community fill, Groups tab shows community cards, paper rows read `C##`
  - Topic map → topic fill, Groups tab shows topic cards, paper rows read `T##`
- **Codes are RANKS, not model ids** (`tCode`/`cCode` over `tRank`/`cRank`): groups are numbered by size, **largest = `T01` / `C01`**, and the number line starts at 01 — never 00, and never the raw topic-model / Leiden id (those stay internal keys for colour and data). Noise reads `—`, folded singletons read `PER`. The Groups list is size-sorted, so the codes run in order down the panel.
- **Left panel is Papers | Groups** — one seg, and inside Groups the search box sits directly under it (no second seg).
- **Year colouring is a style, not a lens**: the network Style panel leads with `Color by · Community | Year` (`.xp-cby`, `_nvCby`; the `nodeColor` tweak seeds it). Community fill is the default; Year restores the `networkPalette` ramp and the year legend. Colouring publishes its **own** hook — `data-cby="group"|"year"` on `.pc-root`, which the two legend bands (`.nv-leg-gp` / `.nv-leg-yr`) key off. Never reuse `data-lens` for colouring: under one-control the network’s lens is always `cit`, so a lens-keyed legend can never follow the Color-by seg. Grouping is unaffected — the left panel still groups by community either way.
- **ⓘ How this was computed** sits beside the view switcher (`.gl-head`), describing whichever grouping the current view carries — method · space · group count · modularity · NMI/ARI agreement with the other partition. Hidden on the review artifact.
- Everything resolves through `glList/glId/glColor/glInk/glCode/glName/glWord`, so cards, codes, drills and canvas colours can never disagree.
- **Palette**: `COMMUNITY_COLORS` in `community-data.js` is the same 12 hues as `TOPIC_COLORS`, rotated by 5 — same family, different partition, and `C01` never lands on `T01`’s ink. Peripheral/noise = `--muted2`.

## Topic map

**Visual grammar matches the citation network** (the two canvases must read as one family, not scatter-plot vs. cartoon):

- **Area carries citations**, log-scaled (`_wl` = log1p of the max) → radius 2.5–13px × a mild zoom factor (0.8–1.55). Uniform dots read as polka dots; weighted circles read as a field of papers. Noise points are 0.62× and fainter.
- **Translucent fill + same-hue outline**: fill at α .84 (noise .55), stroke = the point's own colour mixed 55% toward the **canvas-luminance-chosen anchor** — `--fg` on light paper, `--canvas` on dark themes (mixing toward a light `--fg` on a dark canvas makes the outline brighter than its fill and every point gets a glare ring) — at α×.85, hairline (0.6–1.4px). Never an ink/near-black ring — that is what made the old map look cartoonish.

## Star / save control (one contract, no second implementation)

The `.pr-star` on a paper card is **one component with one owner**. It vanished twice from the Build sidebar because three different pieces of code each owned part of it; these rules exist so that cannot recur. Check all four whenever you touch paper-card markup.

1. **`prCardInner(p, {star:true})` is the ONLY thing that builds a star.** Callers wire behaviour onto the existing `.pr-star`; they never create, clone, or re-append one. A row repaint drops any stray `.pr-star` before re-appending kept children (`prPaint`), so a duplicate can't survive.
2. **Move it by semantic anchor only.** The legal targets are `.pr-meta` (the icon meta line, for in-flow placement) or the row itself (absolute, right-anchored default). **Never `row.querySelector('div')`** — that positional selector is what put the star inside the line-clamped `.pr-title`, where it laid out on line 3 and was clipped to nothing.
3. **Visibility is CSS state, never a JS-set inline opacity.** One rule pair per page: `.pr .pr-star{opacity:0}` + `.pr:hover .pr-star, .pr .pr-star:focus-visible, .pr .pr-star[data-saved="1"]{opacity:1}`. JS only sets `data-saved` and the svg `fill`/`stroke` (`--star` → `--accent` when saved). Coarse-pointer blocks raise the resting opacity to `.55`; Home's `.hw-seed` rows carry the same pair scoped to their own class.
4. **Placement is deterministic, never order-dependent.** The star stays where `prCardInner` put it: absolute against the row's right edge, with `padding-right:46px` reserved on the row. `wireAbstract` no longer relocates it — doing so made the layout depend on whether `paper-row.js` had painted the row before mount (in-flow on `.pr-meta` at 18px if yes, absolute at 46px if no: two layouts for one page). Any code that wants a control on the meta line must check the `.pr-meta` anchor exists at that moment, and must not move the star.\n5. **Verify by hover, not by screenshot.** At rest the star is *supposed* to be invisible, so a broken star and a correct one look identical in any still image — that is why both regressions shipped. A change to paper-card markup is only verified once a hover (or `data-saved="1"`) has been shown to reveal it, and the star's rect has been confirmed inside the row, not inside `.pr-title`. Allow ~300ms for the `.16s` opacity transition before reading a computed value.

Who asks for a star: Build's sidebar rows (`star:true` via `prPaint`) and Home's wizard seed rows. Runs and Explore rows carry no star — their staging control is the picker's own `.kp-star` (§ Corpus picker), which follows the same star vocabulary (`--star` outline → filled) but is its own component with its own markup.

## Card ↔ canvas interaction contract (Runs + Explore · network AND topic map)

NOT the paper treatment: no neighbour/edge work, and noise/peripheral-only exceptions follow the card (`id < 0` never marks).

## Vocabulary: lens vs. membership (project-wide, non-negotiable)

Two things in this product narrow a set of papers, and users conflate them unless the words stay separate. Never invent a third word for either.

- **Filter = a lens.** The papers-panel `Filter` (and Explore's) changes **what you see**. It never adds or removes a paper from the corpus, is never versioned, and costs nothing. Its button carries a `title` saying so.
- **Eligibility criteria = membership.** The run's Year / Citation / Keyword / LLM criteria decide **who is in the corpus** — the systematic-review term, used verbatim in the UI ("Eligibility criteria"). Editing them and re-screening **appends a version**; it can cost money and time.
- The verbs follow from that: you *filter* a list, you *re-screen* papers, you *accept / reject / rescue* a paper, you *grow* or *merge* a corpus. "Re-filter" is retired everywhere (chain kind is `rescreen`); a paper dropped by a re-screen reads `Re-screen` in its why chip.
- **Cost is named only where it is spent** — never as an ambient warning next to a field. Nothing in the criteria editor mentions dollars; the Apply confirm popover states papers, ≈ $, minutes, and pinned-kept, and only then.

## Pipeline spine (Runs · Progress pane)

**ONE renderer draws the live run and a completed run** (`rnPipeHtml(live)`) — they always carried the same information (step, code, seen → kept), so a second "flowchart" drawing for completed runs was deleted (`.rn-fstep`/`.rn-fcon` are gone). Rows are `.rn-step` (`data-i`, `data-ran`, `data-ghost`, padding 8×10, r10): kind icon + name + ✓ + mono code, then a counts line (`2.6k seen → 57 kept`, exact numbers in `title`; `Pending` / `not run` otherwise). The active step keeps its progress bar + stage cascade. **No per-step taper bar** — the counts already say it. Boundaries come from rhythm, hover wash and indent — **never from a card border around each step**.

**Parallelism is stated in words and arithmetic, never in topology.** The list is the form (one row = one step); the graph is recovered by reading, not by decoding lines — a general user must be able to picture Build's flow chart from it. One wave, three parts:
- `.rn-fork` caption opens the wave: fork glyph + `In parallel` mono caps tag + hairline + a right `.rn-fnote` stating the **shared input** ("both read the 7 seeds" / "both read 53 papers"; `all N read …` for 3+ branches). The note truncates rather than wrapping.
- `.rn-branch` holds the wave's steps indented 16px behind ONE 1.5px `--dot-sep` rule — **indent depth is the only nesting; never a tinted well or a card per branch** (block-in-block was tried and rejected). A branch that is itself a chain of steps gets a quiet `.rn-bhead` letter head (`A` + "2 steps, in order"); single-step branches get none.
- `.rn-join` closes it with the **merge arithmetic** — `45 + 8 → 53 papers continue` (last wave: `… → 135 papers join the corpus`). A join line always states that WAVE’s contribution, never the run total — the accepted total lives on the v0 row and the hero, the join glyph leading. It renders only when every step of the wave is `done`; a wave still running shows no join line.

Sequential steps are plain rows on the panel; `.rn-vcon` 1.5px ticks (margin-left 16px, aligned to the icon column) join wave to wave and continue unbroken into the `.rn-vrow` version chain, so pipeline and versions read as one spine.

## No linked or synced steps (Build pipeline)

A pipeline step is **always independent**. The add menu (Add step after / Run alongside) offers `Copy an existing searcher` — picking one clones that searcher’s filters and params into a brand-new step. There is no link, no sync, no `syncOf`: no link glyph on the block cards, no announcement banner in the configuration panel, and editing one step never touches another. Duplicate behaves the same way. Reintroducing linked copies is a regression: it was removed because two steps that silently edit each other is not something a user can hold in their head.

## Consequential decisions: one global modal

A decision that changes **what Explore and the agent read** (restore a version, delete a run) is never an inline popover. It opens **one centered modal over the whole app**: fixed scrim `rgba(18,16,14,.52)` over the frame, a 430px ink card (`color-mix(in oklab, var(--fg) 95%, #000)`, r16, `--bg` text), serif 20px title, 13.5px body, two high-contrast buttons bottom-right (ghost Cancel with a `--bg` hairline; solid `--bg` confirm with an `--fg` label, or `--error` on white when `tone:'danger'`). Esc and scrim click cancel, Enter confirms, the confirm button takes focus. `klModal({title, body, confirmLabel, tone, onConfirm})` in Runs owns it.

**Copy rule**: say what changes, in a sentence a stranger understands. Title asks the question in product terms ("Read v1 from now on?"), body states the consequence and the safety net ("Explore and the agent will read v1 instead of v3 … your newer versions stay in this run's history"), the button repeats the verb and its object ("Restore v1"). No jargon nouns as headlines, no em dashes, no dot-separated fragments.

Light, reversible confirms (paste filters, apply to all, discard a draft) stay as anchored `.cfg-confirm` popovers.

## Forbidden typography (hard rules)

Three bans, project-wide, in every user-visible string (labels, chips, tooltips, banners, menus, tweak option labels):

1. **No monospace.** The UI has one type system: 'Hanken Grotesk' for UI, 'Newsreader' for reading. Run ids, version chips, step codes, T##/C## codes, token counts and model names all render in the sans face with `font-variant-numeric:tabular-nums` (+ `letter-spacing:.01em` on code-ish chips) for column alignment. Mono reads like a programmer's console and is never used, not even for ids or API keys. **Form controls do not inherit `font-family`**, so every page's helmet carries `.pc-root button, .pc-root input, .pc-root textarea, .pc-root select{ font-family:inherit; }`. Without it, removing a control's mono declaration silently drops it to the browser default (Arial). Never delete that rule.
2. **No dot separators.** `·` never joins two facts. Use a double non-breaking space (`\u00a0\u00a0`) inside a single string, or separate spans in a flex row with `gap`. Author lists join with `, ` ( `; ` when the names themselves contain commas, e.g. "Zhang, Q; Li, H"); the internal data delimiter stays ` · ` and is converted at display time (`prAuthors` in paper-row.js, `auList` in Explore).
3. **No em dashes.** `—` never appears in copy. A label plus its gloss takes a colon ("Working corpus: what Explore and the agent read"); a parenthetical takes a comma or parentheses. An **absent value** renders as an en dash (`–`), which stays legal for that and for numeric ranges ("2022–2026", "1–10 of 343").

**Run ids read as words**: internal ids stay `RUN-37`, but every display goes through `rid()` (Runs) → `Run 37` (leading zeros dropped: `RUN-06` → `Run 6`). Never print a raw id, and never follow it with a separator glyph: the Explore corpus chip is `Run 37` + a muted `v3` set apart by spacing alone. **Never concatenate an operation name after a version number** in a one-line label; version + delta only ("Corpus updated to v3  +38"). Operation names belong in their own column of a list row (chain rows, version popovers).

## Corpus refinement & versions (Runs page)

**Model.** A run is an immutable execution; each run roots a **refinement chain** whose `v0` = the raw run results. Four operation kinds append versions: **Edit** (manual reject/rescue — consecutive edits coalesce into the tip edit version; manual verdicts are **pins** that outrank any later re-filter, and a rescue bypasses every filter), **Re-filter** (re-screens the whole seen pool — accepted + rejected — against changed thresholds; metadata filters are instant, LLM changes carry a cost note), **Grow** (a delta-run: Forward / Backward / Semantic / all-three expansion from the current corpus, screened by the current filters), **Merge** (import another run's accepted set, duplicates skipped; merged papers arrive pinned). Restore is chain-internal and append-only: restoring to `vK` makes it the tip and moves later versions into a collapsed **Superseded** group — nothing is deleted, and the only cross-run channel is Merge. The run's own record (PRISMA counts, All-runs row) always shows v0.

## What Explore reads (the working corpus, project-wide)

**Neither "working" nor mechanism-speak ships in the UI.** Name the relationship from the user's side, short and human: the chip is `In Explore` (header of the viewed run, All-runs row, and the chain-tip version row it actually points at) — a quiet `.rr-work` pill (10.5px 600, fg-tint fill, target glyph), never a caps-tracked shouting chip ("READ BY EXPLORE" read machine-generated). The run ⋯ menu verb is `Show in Explore`, Explore’s popover heading stays `What Explore reads`, and tooltips spell it out ("Explore and the agent read this run and this version"). "Working corpus" survives only as the internal name in this document and in code.

**One pointer.** A project has exactly ONE **working corpus** — `(run, active version)`; default = the most recent completed/stopped run at its chain tip. It is the only corpus Explore, the agent, and the topic/community models read. Mental model: **Runs is the past (time machine), Explore is the present** — Explore never grows a run/version picker.

- **Moving the pointer happens on the Runs page only**: a new run completing, Restore inside the working run's chain, or **“Show in Explore”** in the All-runs popover row ⋯ menu (`.rr-menu`, which also holds Delete run — the old hover-trash was folded into it). The pointed-at run carries the quiet `In Explore` chip (All-runs row, plus the panel header while viewed; the chain-tip version row carries the same marker). Setting it acks by moving the chips (no modal, no banner spam).
- **Provenance stamps, not locks.** Everything generated records the version it was computed from: topic model & communities (per-version cache — recompute on demand via the invite state, never silently, never discarding an older cache), literature-review artifacts (`built from v2`), agent threads (per-message). **Staleness is information, not invalidation** — the one pattern is the warning-tint chip (`.gl-stale` vocabulary) + an explicit refresh action stating what it costs; nothing auto-recomputes, nothing gets wiped.
- **Threads never hard-pin.** A corpus move renders a **seam divider** in the thread (`thSeam`: hairlines flanking `Corpus updated to v3 · +38`). **Never append the operation name after a version number** in a one-line label — version + delta only; the operation name belongs in a list row's own column (chain rows, version popovers), never concatenated into a chip, seam, or bar that has to fit a narrow panel; messages above it honestly reflect the older version, new sends read the current corpus. Attachments live by paper id; a paper removed by the move ghosts its chip.
- **Artifacts**: when the corpus is ahead of the artifact's stamp, the thread card and the artifact header carry a `Built from v2` warning chip; clicking it opens the standard confirm popover ("Re-check citations against v3") → a working beat → the chip clears and the thread lands a settled receipt line (`Re-checked 42 citations against v3 · all still in the corpus`). The draft itself is never mutated without that confirm.
- **Explore corpus chip** (`.gl-vchip`): a readable control, not a ghost — 1px `--border`, `color-mix(in oklab, var(--fg) 5%, transparent)` fill, 12px 600 `--fg` `Run 37` with the version in `--accent` 700; hover deepens the fill to 10% and darkens the border. Which corpus you are looking at is primary information, so it reads at a glance (but never as a black pill). It opens `.gl-vpop` — caps `What Explore reads` + paper count, then the chain as **clickable rows** (`.gl-vrow`, current row checked): clicking a version deep-links to the Runs page viewing it (`xpGotoRuns` — dispatches `kl-goto-runs {run, v}` for Runs' document listener, then clicks the top-bar Runs tab so the shell navigates); footer = one short line + an **Open Runs ›** button. The popover is an entry point, never a dead end — but corpus switching itself still happens only on Runs.

## Import papers (a resolver, not a file manager)

Bulk-adding papers (seed sets, refinement adds) is ONE flow with format-specific parsers: **extract references → resolve on Semantic Scholar → match-review → add**. Files are transient input — never a stored library, no Drive-style manager.

- **Entry points**: the New-project wizard's Seed papers step, Runs' Add papers panel, AND Build's seed search sidebar (`.sb-imode`) each carry a `Search | Import` seg — the label is "Import", never "Import a file" (the flow takes many files, folders, and .zip). Same grammar in all three; Build adds go through `seedImport` (starred seeds, title-deduped).
- **Formats**: `.bib` / `.ris` / `.csv` / `.txt` DOI-or-arXiv lists / `.pdf` (metadata + title match) — multi-select and folder drop are the norm; `.zip` is accepted as a convenience, never required.
- **Stages**: dashed dropzone (browse button + a `sample refs.bib` demo link) → per-file parse rows (EXT badge, name, spinner → `34 references found` / per-file error) → the **match-review list**.
- **Match-review rows** (checkbox + extracted title + `Author · year · from refs.bib` sub): states are **Matched** (auto-checked, S2 record shown), **Ambiguous** (`2 matches` pill → candidate popover; unchecked until resolved), **Already in corpus / seed set** (dimmed, disabled, chip — dedupe by S2 id), **No match** (error-tint pill + reason + source line; **not addable** — unmatched entries are always reported by row AND counted in the footer, never silently dropped).
- **Footer**: primary `Add N papers` + muted error note `3 couldn't be matched`. Adds go through the surface's existing path (wizard → starred seeds; Runs → pinned `USR-01` rows in the tip Edit version).
- **PDF bonus**: an uploaded PDF attaches its full text to the matched record (`pdfSrc:'user'`) — its PDF mark tooltip reads "from your import".

## PDF availability (full text)

Whether the agent can read a paper in depth is an operational property, shown quietly where papers render and loudly where money/time is spent.

- **Row mark — presence only, but salient**: `KLPaperRow.prPdf(p)` renders an **open-padlock + `Full text`** pair in green (`color-mix(in oklab, var(--success) 72%, var(--fg))`, 600 weight) when full text is available, and NOTHING otherwise. The reference is Nature's *Open Access* label, not Scholar's `[PDF]` link: this is not a place to click, it is an **access signal** — it tells the reader whether the agent can read that paper in depth, so it must be scannable down a column. Absence stays unlabelled (a list's default state) and surfaces at the decision points below + the filter. Green here is a status colour, not the accent — selection remains accent-only.
- **Decision points carry the aggregate**: the skill task card's scope phase settles to `500 papers · full text for 312`; a generic send with attached papers settles `Read 3 papers · full text for 2`. Same cost-honesty rule as § Vocabulary — capability limits stated at the moment of use, not as ambient warnings.
- **Filter**: the papers filter panel gains a `PDF · Full text available` switch (counts toward `Filter · n`), beside the Cited-in-draft row.

## In this corpus (citing passages)

Reception data on a paper: **what the other papers in the corpus say when they cite it**. Vocabulary is fixed — module title **In this corpus**, each quote is a **passage**, the skill is **What the corpus says**. Never "smart citations", never supporting/contrasting verdicts (we show what was said, not a machine verdict on it).

- **Placement**: the abstract drill keeps its order — venue, title, meta, authors, groups, links, **Abstract**, then the module under a `--divider` rule. It is never above the abstract and never a drawer: the meta row carries a `.ab-ccjump` pill (`Cited by N here`) that scrolls to it, so the signal is on the first screen and the body is one click away.
- **The panel is NOT a second answer surface.** The header’s **Summarize in chat** button drafts the send in the agent panel — skill pill + paper attachment + a prompt in the composer, focused, *not sent* — and the summary is written in the thread like any other answer. No summary card, no progress block, no state machine in the side panel.
- **Flat by construction — at most two levels, no boxes inside boxes.** The panel itself is the card; passages are plain rows on it, following the community/topic paper-list grammar (`.tp-pr`): no per-paper card, no per-passage card, **no left quote rules**. Header row (topic swatch + `T##` + `Surname et al. · year` over the title + passage count + a hover-only ↗ that opens that paper) → its passages, each a 9.5px caps section label over serif 13.5/1.52 text, separated by an inset hairline; a `--divider` line + 6px gap separates one citing paper from the next. Hover = `--row-hover` on the row’s own 9px radius.
- **Controls**: search field + `.cc-count` on one line, then a **one-line horizontally scrolling facet rail** of section chips (Introduction / Methods / Results / Discussion / Related work / Other sections / Unlabelled) whose counts are computed over the unfiltered set so they never move. Searching or facet-filtering auto-expands every paper and `<mark>`s matches.
- **Scale — page over PAPERS, step over passages.** The citing paper is the unit a reader holds, so the module pages 8 **papers** at a time with the papers list's own pager component (‹ › + `1–8 of 35 papers`; paging scrolls the module header back to the top), and each paper opens in two steps — 2 passages → 8 (`N more from this paper`) → all (`Show all N passages`). Nothing ever dumps an unbounded list into the drill, and the drill's scroll length stays the same whether the corpus holds 40 passages or 4,000; search + facets are the real instrument for finding one.
- The count on a paper row is **icon-led** (speech-bubble glyph + number, tooltip `N citing passages`) — a bare number in a row is unreadable.
- **Canvas tie-in** (`CitationNetwork.setTrace(id)`): hovering a passage keeps the subject **selected** (accent fill + rings) and lights ONLY the citing node and the edge between them — the edge is drawn thicker over the node layer, every other neighbour recedes with the graph. Click **pins** the trace (row goes `--icon-bg` + an accent dot by the section label) and flies the camera to the pair. The same trace fires from the `.cc-ref` chips in the thread’s summary. Exiting the abstract clears it.
- **Empty / unavailable**: a paper nothing here cites gets a low dashed row ("No paper in this corpus cites this one." + why-it’s-empty line) — present but quiet, no jump pill, no Summarize button. The `citationContext: Not indexed` tweak shows the warning-toned unavailable state with **Try again**; the skill answers in kind instead of faking a summary.
- **The skill** (`/what-the-corpus-says`, k `corpus-says`) runs a standard task card — *Find citing papers* → *Pull the passages* (determinate, N / M) → *Synthesize* — then streams the summary as ordinary assistant prose carrying `.cc-ref` chips (`Gao 2024`), and settles a status line with the totals.

## Streaming agent text

Agent-written prose is **typed, never pasted** — `stream-text.js` (`streamHtml(host, html, {cps, onTick, onDone})`) parses the fragment once, empties its text nodes and refills them word by word behind the shared `.rv-caret`, revealing each block as its first word lands and auto-following the scroll. Used by `thMd(html, {stream:true})` for assistant answers in the thread and by the corpus summary; the literature-review draft keeps its own block-level stream on the canvas.

## Skill task cards (agent thread)

Two tiers of agent status — never a card per tool call, never a bare spinner for a minutes-long skill:

- **Quick actions** (sub-second → a few seconds, no skill attached) stay the 12px status lines (spinner → check + past-tense summary). **Any send with a skill attached renders a task card** — including the generic-answer path (thGeneric): Scope the request → Read ‹scope› (determinate bar over the real count) → Synthesize, then collapse + prose. A `/literature-review` send while a draft already exists keeps the draft, says so, and re-links the artifact card.
- **A skill run** (e.g. `/literature-review`) is ONE `.th-task` card: `--card2` r12; header = 22px icon + skill name 13/600 + right side **Stop** ghost while running → `N steps · Ns` + chevron when done (header click toggles collapse). Body = phase rows: state icon (queued ring · spinner · check) + label + right live counter (tabular); the active phase carries a **3px determinate bar only when a real denominator exists** (track `--border`, fill `--fg2` — ink, the dual-range vocabulary; accent stays selection-only). Un-countable phases (drafting) get the spinner and a live counter, **never a fake bar**.
- **Completion collapses the card** to one settled header row; the summary prose + artifact card land after it, so the thread's resting state stays clean. Restored threads render the collapsed card (not loose status lines). **Stop** is live through the pre-draft phases: it bumps the generation guard, marks `Stopped after k of n steps`, and ghosts the remaining rows (once drafting starts, progress lives on the canvas and Stop hides).

## Pressed & open states (buttons, rows, pills)

- **Pressed tint** (Outlook-style): every tappable row/card shows `background:color-mix(in oklab, var(--fg) 9%, transparent)` on `:active` (instant, `transition-duration:0s`), suppressed while an inner button is the active target (`:not(:has(button:active))`). Applied to `.pr`, `.rn-run/.rn-step/.rn-vrow/.rf-launch`, `.tm-card`, `.hm-prow/.hm-crow`, menu items. iOS needs a document `touchstart` listener for CSS `:active` — paper-row.js installs it once per document.
- **Open state**: every popover opener toggles `aria-expanded`, and the shared rule `[aria-expanded="true"]{ background:color-mix(in oklab, var(--fg) 10%, transparent) }` makes the open state clearly darker than hover on any display. Never leave an opener's open paint behind after close (and on touch, neutralize sticky `:hover` for openers).
- **Pills are controls.** Anything drawn as a pill/chip must act when clicked: the Runs header version chip jumps to the version chain (`rnGotoVersions`: Progress pane + scroll + row flash), the header `In Explore` chip opens Explore. A pill that can never act should not look like a pill.
- **Boundary rule**: header status text never collides with the frame — the least-load token (the date) hides at compact/narrow (`.rn-stat-date`); words like Completed never abbreviate.
- **Touch reorder**: drag is the one reorder gesture on touch — the up/down arrow pairs (`.cf-tool[data-act=up/down]`, `.rsc-mv`) hide under `@media (hover:none)`.

## Type minimums (audited 2026-08-11, iPad pass)

## Feedback & structure rules (2026-08-11 review pass)

- **Copy actions answer on the button itself**: label swaps to "Copied" + `--success` ink + success-tinted border for ~1.4s, with a subtle scale pop (`abCopyFlash`, all abstract drills). Any future copy/export control follows this — never a color-only blink.
- **Explore Download menu**: same anatomy as Runs' (`.tb-dl-wrap` / `.tb-dl-menu`), scoped to the corpus Explore reads (Run 37 v3): Corpus papers CSV, Literature review Markdown, Full bundle.
- **Pipeline canvas**: drag can drop a step on EITHER side of a trunk card (left fan slot inserts as the left branch). The step count on a card is words, not pips — "6 filters" (the 5-pip cap lied about longer pipelines; text scales).
- **Reuse menu lists originals only**: a step created via "copy its settings" is marked `reused` and never re-offered, so copies can't snowball the menu.
- **One job per lens** (filter pipeline): a step never carries two filters doing the same screen — one Year, one Citation, and per keyword/LLM type at most one Title and one Abstract pass. The add-menu dims exhausted options (40% opacity + title + toast on tap explaining which filter to edit instead).
- **Import review = triage order + progressive disclosure**: sections run Needs a decision → Couldn't match → Matched → Already-in-corpus; attention sections open, bulk sections collapse to a count header ("Matched 42 · Show") so failures are never buried under matched rows. Section headers are toggles (chevron + count).


## Drill-in choreography

A drill never appears — it composes. The panel keeps the standard drill slide (opacity + 12px translateX), and its CONTENT enters in reading order: hero metrics rise with a 36ms stagger, then each pipeline stage lands (8px rise, 55ms apart) with its unit-squares sweeping left-to-right (13ms/square, capped at 300ms, slight overshoot pop). Fast, deterministic, never over 1s total (`rdEnterFx`, Runs step drill — the reference implementation for any future bar/stat drill).

## Canvas drag slots: neighbour fallbacks

Every trunk drop slot stores BOTH neighbour ids. Pulling the dragged step out of a 2-branch group dissolves that group during prune, killing the id a slot pointed at — the move then resolves against the surviving neighbour (insert after prev / trunk tail push) instead of being filtered out. This is why "between two groups" and "above a group" are always valid targets now.
